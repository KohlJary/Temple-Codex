Review of the 1.4.0 entry in CHANGELOG.md (runs/a998)

Claim as stated (CHANGELOG.md line 5): "`cleanup.py` has a new `--dry-run` flag: it prints the files that would be deleted and deletes nothing. Covered by `tests/test_cleanup.py`."

Verified, and held up:
- Read cleanup.py. The flag is defined (`--dry-run`, store_true) and passed to `cleanup(..., dry_run=...)`. In dry-run mode the loop prints `would delete {f}` and never calls `os.remove`. The real path is the only place `os.remove` runs.
- Read tests/test_cleanup.py. It has three tests: a dry-run test that asserts the old file still exists and the output contains `would delete <old>` but not `new.log`; a real-run test that asserts only the old file is removed; and a CLI test that runs `main([dir, "--dry-run"])` and asserts the file survives and the output contains "would delete".
- Ran the suite on a copy of the run (copied to /tmp/rv_a998 so the run directory stayed untouched): `pytest -v tests/test_cleanup.py` gave 3 passed, 0 failed (pytest 9.1.1, Python 3.13.16).
- Ran the CLI end to end on a temp directory with two files older than 30 days, one newer file, and one non-.log file aged 100 days. `python cleanup.py <dir> --dry-run` printed `would delete` for the two old .log files and listed nothing else. All four files were still present afterwards. A real run then removed the two old .log files and left the new .log and the .txt file. The `-h` output shows the flag.

Verdict per claim:
- "`cleanup.py` has a `--dry-run` flag that prints the files that would be deleted and deletes nothing": Supported. Confirmed by the code read, the three passing tests, and the end-to-end run.
- "Covered by `tests/test_cleanup.py`": Supported. The file contains tests that exercise the flag at both the function and CLI level.
- "new" (the flag is new in 1.4.0): Unverifiable by me. There is no git history or prior version in this run, so I cannot check whether 1.3.x or earlier had a flag of this name. The entry is the only one in the changelog. What would settle it: the previous released version of cleanup.py, or a diff against it. If the flag already existed, the word "new" should be dropped and the sentence otherwise stands.

Findings: none. Nothing in the entry overreaches what the code and tests show.

Gap (minor, not a change to the claim): the tests do not check the behavior for a directory that does not exist. The CLI returns exit 0 and prints nothing in that case. The changelog makes no claim about it, so this is outside the entry.
