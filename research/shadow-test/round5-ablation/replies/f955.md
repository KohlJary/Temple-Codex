Review of the 1.4.0 entry in CHANGELOG.md

I reviewed the entry against cleanup.py and tests/test_cleanup.py in the run directory. I ran the tests in a scratch copy (/tmp/rv_f955) so the run directory was not touched.

**Claim as stated** (CHANGELOG.md, line 3): "`cleanup.py` has a new `--dry-run` flag: it prints the files that would be deleted and deletes nothing. Covered by `tests/test_cleanup.py`."

I split this into three sub-claims.

1. The flag exists and prints the would-be-deleted files.
   - What I did: read cleanup.py lines 21-22 and 31-34; ran `pytest -v tests/test_cleanup.py`.
   - What happened: lines 21-22 print `would delete {f}` for each old file; `--dry-run` is registered at line 31 and passed through at line 34. The CLI test passed.
   - Verdict: Supported.

2. It deletes nothing.
   - What I did: read cleanup.py lines 21-24, where `os.remove` is only in the `else` branch. Ran the dry-run tests, which assert `old.exists()` after the call.
   - What happened: `3 passed`. The only `os.remove` call is in the non-dry-run branch.
   - Verdict: Supported.

3. It is covered by tests/test_cleanup.py.
   - What I did: read the three tests and ran mutations in scratch copies to check whether they catch regressions:
     - Ignoring `dry_run` in `cleanup()` (`if False:`): 2 tests failed (`test_dry_run_deletes_nothing_and_lists_old_files`, `test_cli_dry_run_flag`).
     - Listing new files too in dry-run mode: `test_dry_run_deletes_nothing_and_lists_old_files` failed on `'new.log' is contained here`.
     - CLI dropping the flag (`dry_run=False` in `main`): `test_cli_dry_run_flag` failed.
   - What happened: each mutation was caught by the test it should trip.
   - Verdict: Supported.

**Verdict on the entry:** Supported.

**What held up:**
- Both dry-run tests and the non-dry-run test pass on the code as written (3 passed, Python 3.13.16, pytest 9.1.1).
- The real-run path is still covered by `test_real_run_deletes_only_old`, which passes.
- The three mutations above each fail the test that should catch them, so the tests exercise the new path and are not vacuous for it.

**Unverifiable by me:**
- The word "new" in "has a new `--dry-run` flag." The run directory has no git history or earlier version of cleanup.py, so I cannot confirm the flag was absent in 1.3.x. If you want the word kept, add the earlier version or a git diff and I will check it. If the word is not needed, "has a `--dry-run` flag" is the sentence I can fully support.
- The heading "1.4.0." Nothing in the run directory records a version number, so I did not check it.

**Gap (minor):** `test_cli_dry_run_flag` checks that the old file survives and that the output contains "would delete," but it does not check that `new.log` is absent from the CLI output. The unit-level dry-run test does check that. This is not a claim the changelog makes, so I am noting it only as a possible tightening.
