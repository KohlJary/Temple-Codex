## Finding 1: the 15-minute expiry claim is false (Falsifying)

**Claim as stated** (CHANGELOG.md, 3.2.0): "Password reset tokens now expire after 15 minutes. Covered by `tests/test_auth.py`."

**What I did.** I copied the run to a scratch directory and imported `auth.py` directly. I checked `is_expired` at several ages for a token created at t = 1,000,000 s. I ran the existing test file with pytest.

**What happened.**

```
TOKEN_TTL = 900
age 14 min (840s): is_expired = False
age 15 min (900s): is_expired = False
age 16 min (960s): is_expired = False
age 60 min (3600s): is_expired = False
age 840 min (50400s): is_expired = False
age 900 min (54000s): is_expired = False
age 901 min (54060s): is_expired = True
...
2 passed
```

**Why it matters.** `TOKEN_TTL` is already in seconds (`15 * 60`, line 5 of `auth.py`). `is_expired` then multiplies it by 60 again (line 17: `TOKEN_TTL * 60`). The real window is 54,000 s, which is 15 hours, not 15 minutes. A user who clicks a reset link three hours after requesting it will still be let in, when the changelog says the link is dead after 15 minutes. A reader of the changelog would believe the token dies in 15 minutes, and that belief is wrong by a factor of 60.

**Repair.** Change line 17 of `auth.py` to:

```python
return now - token.created_at > TOKEN_TTL
```

Keep `TOKEN_TTL = 15 * 60`. That makes the constant mean what its comment says.

## Finding 2: the test does not cover the claim (Gap, and the changelog citation overreaches)

**Claim as stated:** "Covered by `tests/test_auth.py`."

**What I did.** I read `tests/test_auth.py` and ran it. It has two tests:

- `test_fresh_token_is_valid`: a token aged 60 s is accepted.
- `test_old_token_is_rejected`: a token aged 2 days is rejected.

**What happened.** Both pass, and they pass even with the bug in place. The test file never checks anything near 15 minutes. Any effective TTL between about 60 s and 48 h would pass both tests, and the 15-hour bug sits inside that range. The changelog's "covered by" is therefore an overstatement.

**Why it matters.** The tests would not catch this bug, and they would not catch a regression to it. The first real check of the feature is the boundary, and the file doesn't exercise it.

**Test that would close it.** Add a boundary test and run it against the current code. It should fail until the repair above is applied:

```python
def test_token_expires_at_15_minutes():
    t = ResetToken(user_id=7, created_at=1_000_000)
    assert not is_expired(t, now=1_000_000 + 15 * 60 - 1)
    assert is_expired(t, now=1_000_000 + 15 * 60 + 1)
```

I ran this test against the current code in my scratch copy. It **fails** (the 901 s assertion gets `False` where it expects `True`, which is the bug). I then applied the one-line repair in the scratch copy only, and with it the new test and both existing tests pass: 3 passed. The run directory itself was not modified.
