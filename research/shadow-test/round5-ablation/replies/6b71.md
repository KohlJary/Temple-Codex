# Review of CHANGELOG.md, 1.4.0

Claim as examined (CHANGELOG.md, 1.4.0): "`cleanup.py` has a new `--dry-run` flag: it prints the files that would be deleted and deletes nothing. Covered by `tests/test_cleanup.py`."

Restated narrowly, this is three testable sentences:
1. `python cleanup.py DIR --dry-run` prints one line per old `*.log` file (older than 30 days) and removes nothing.
2. Without the flag, behavior is unchanged: old logs are deleted.
3. `tests/test_cleanup.py` covers the flag.

## What held up

- **Test suite (ran it, on a copy in /tmp/rv_6b71):** `python -m pytest -q` gave `3 passed in 0.03s`.
- **CLI behavior (ran it):** I made a dir with `a.log` (60 days old), `b.log` (new) and `c.txt` (60 days old, not a log). `python cleanup.py DIR --dry-run` printed `would delete /tmp/rv_6b71/d/a.log`, exited 0, and all three files were still present afterward. Only the old `.log` file was listed.
- **Non-dry-run path (ran it):** after I changed the call to ignore the flag (see next item), the same command without `--dry-run` deleted `a.log` and left `b.log` and `c.txt`. Deletion still works.
- **"Covered by tests" is real, not nominal (mutation check):** I changed `dry_run=a.dry_run` to `dry_run=False` in `main()` on my copy. `test_cli_dry_run_flag` then failed (1 failed, 2 passed). So the test exercises the flag through argparse, not just the function. The original code in the runs dir is untouched.

## Findings

None. I tried to falsify each part of the claim and could not.

## Notes (true, checked, nothing needs to change)

- **Note:** The entry says "prints the files that would be deleted." The output is a line `would delete <path>` per file, not a bare list of paths. This is consistent with the claim; mentioning it only so nobody scripts against a bare-path format.
- **Note:** The "old" threshold (30 days, `AGE_DAYS`) is not stated in the entry and is not new in 1.4.0. I did not check whether earlier versions behaved differently, since there is no history in the directory.

## What I did not check

- I only read the files present: `CHANGELOG.md`, `cleanup.py`, and one test file. There is no earlier version or version metadata in the directory, so I could not confirm that `--dry-run` is "new" in 1.4.0 (as opposed to existing earlier) or that 1.4.0 matches any release tag.
- I did not test unusual inputs such as symlinks, directories named `*.log`, or permission errors. The changelog makes no claim about them.

## Verdicts

- "`--dry-run` prints the files that would be deleted and deletes nothing": **Supported.** Confirmed by CLI run and tests.
- "Covered by `tests/test_cleanup.py`": **Supported.** Confirmed by test run and by a mutation that the CLI test caught.
- "New in 1.4.0": **Unverifiable by me.** I would need the repo history or the previous release's `cleanup.py`.
