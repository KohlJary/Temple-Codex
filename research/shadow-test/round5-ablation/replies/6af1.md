# Review of CHANGELOG.md, 1.4.0

Claim as stated (CHANGELOG.md, 1.4.0): "`cleanup.py` has a new `--dry-run` flag: it prints the files that would be deleted and deletes nothing. Covered by `tests/test_cleanup.py`."

Narrow restatement, as three testable sentences:
1. `python cleanup.py DIR --dry-run` prints one line per old `*.log` file and removes no files.
2. Without the flag, the same files are deleted.
3. `tests/test_cleanup.py` would fail if (1) broke.

## Findings

None. I have no Falsifying, Overreaching or Gap findings.

## What held up (checked)

- **Tests ran.** `python -m pytest -q tests` gave `3 passed in 0.02s`.
- **Real CLI, dry run.** I made `a.log` and `b.txt`, both backdated 60 days, in a scratch directory. I ran `python cleanup.py . --dry-run`. Output was `would delete a.log`, exit code 0, and both files were still present afterwards.
- **Real CLI, without the flag.** I ran `python cleanup.py .` on the same directory. `a.log` was removed and `b.txt` was left alone, exit code 0. The flag therefore changes behavior, and the non-dry path still deletes.
- **"Covered by tests" is true for the flag wiring.** I copied the project to scratch and changed `main()` to pass `dry_run=False` (ignoring the flag). `test_cli_dry_run_flag` then failed with an AssertionError. The CLI test would catch a broken flag. I did not modify your directory.
- **Read, not run:** `cleanup()` at `cleanup.py` lines 17-25 only calls `os.remove` in the non-dry branch. `test_dry_run_deletes_nothing_and_lists_old_files` checks that old and new files both survive and that only the old file is listed.

## Scope notes

- **Note:** The entry says "the files that would be deleted". The implementation only considers `*.log` files in the top level of `dir`, older than 30 days (non-recursive, fixed `AGE_DAYS`). That matches what the real run deletes, so the dry run is faithful to it. The changelog does not describe the log-only scope. This is already true of the tool before 1.4.0, so I am not asking for a change.
- **Note:** The dry-run listing goes to stdout (the tests confirm this through `capsys`). That is consistent with "prints".
- I only exercised the case where the age threshold is the default and the files are regular files. I did not test symlinks, permission errors or nonexistent directories. The changelog does not claim anything about those, so this is a limit of my examination, not a gap in the claim.

## Verdicts

- "`--dry-run` flag prints the files that would be deleted and deletes nothing": **Supported.** Confirmed by running the CLI and by the tests.
- "Covered by `tests/test_cleanup.py`": **Supported.** Tests pass, and a mutation of the CLI wiring made one of them fail.

Error ledger: none so far.
