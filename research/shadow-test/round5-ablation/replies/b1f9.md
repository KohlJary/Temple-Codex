Review of the 1.4.0 entry in CHANGELOG.md

Entry under review:
> "`cleanup.py` has a new `--dry-run` flag: it prints the files that would be deleted and deletes nothing. Covered by `tests/test_cleanup.py`."

What I ran: I copied the run directory to a scratch folder and ran `pytest -v tests/` there. I did not modify your directory. I also called `main()` directly on a scratch directory holding `old.log` (40 days), `new.log` (1 day) and `old.txt` (40 days), once with `--dry-run` and once without.

Findings

1. Gap (the word "new"). The claim that `--dry-run` is new in 1.4.0 is not something I can check. The run directory has no git history and no earlier version of `cleanup.py` to diff against. The behaviour is consistent with it being new, but I have not confirmed that. To close it, diff `cleanup.py` against the 1.3.x release, or check `git log -p cleanup.py` if you have history. If it is new, the entry is accurate as written.

Held up (verified)

- Dry-run lists and deletes nothing. Running `main([dir, "--dry-run"])` printed `would delete d/old.log` and left the directory as `['new.log', 'old.log', 'old.txt']`. The code path is `cleanup()` in cleanup.py lines 21-22, which prints and skips `os.remove`. Confirmed by running it.
- The real run still deletes. Without the flag, the same directory ended as `['new.log', 'old.txt']`. Only the old `.log` file was removed, which matches the `*.log` glob on line 11.
- The test suite passes: 3 of 3 (`test_dry_run_deletes_nothing_and_lists_old_files`, `test_real_run_deletes_only_old`, `test_cli_dry_run_flag`). I saw each one pass in the `-v` output.
- "Covered by tests/test_cleanup.py" holds. The dry-run path is exercised both through `cleanup(..., dry_run=True)` and through the CLI flag via `main([... "--dry-run"])`, and the tests assert that the file still exists afterwards.
- The `--help` output lists `--dry-run`, so the flag is wired into the parser.

Not a claim, noted for completeness

- A missing directory with `--dry-run` exits 0 and prints nothing. `Path.glob` on a nonexistent directory returns no matches silently. The changelog does not promise anything about this, so no change is needed. If you want it documented, it is a one-line addition.

Verdicts on the claims

- "prints the files that would be deleted and deletes nothing": Supported.
- "Covered by tests/test_cleanup.py": Supported.
- "a new --dry-run flag" (the word "new" relative to 1.3.x): Unverifiable by me, for lack of the prior release. The test that would settle it is the diff described above.

Summary: The entry is accurate for the behaviour it describes. The only open point is whether the flag is new in 1.4.0, which I could not check from this directory.
