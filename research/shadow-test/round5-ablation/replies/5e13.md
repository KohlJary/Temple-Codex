# Review of CHANGELOG.md, 1.4.0

Claim examined (CHANGELOG.md, 1.4.0, the only bullet):
"`cleanup.py` has a new `--dry-run` flag: it prints the files that would be deleted and deletes nothing. Covered by `tests/test_cleanup.py`."

Narrow restatement, as three testable sentences:
1. `python cleanup.py DIR --dry-run` is accepted.
2. With the flag, it prints one line per `*.log` file older than 30 days and removes no files.
3. `tests/test_cleanup.py` exercises that behavior, so a regression would fail the tests.

## What held up

- **Flag exists and works end to end.** I ran it on a copy in /tmp/rv_5e13. I made a directory with `old.log` (mtime 40 days ago), `new.log`, and `sub.txt`, then ran `python cleanup.py /tmp/rv_5e13/d --dry-run`.
  - Output: `would delete /tmp/rv_5e13/d/old.log`, exit code 0.
  - `ls` afterward showed `new.log old.log sub.txt`, so nothing was deleted and `new.log` was not listed.
- **The non-dry run still deletes.** Without the flag, the same directory ended up with `new.log sub.txt` and `old.log` was gone. This confirms the flag is what changes the behavior.
- **The tests pass.** `pytest -q` on a copy gave `3 passed`.
- **The "Covered by" clause is real, not decorative.** I broke the copy in two ways and checked that the tests noticed.
  - Replacing `if dry_run:` with `if False:` gave `2 failed, 1 passed`.
  - Removing the `print` of "would delete" gave `2 failed, 1 passed`.
  - The failing tests were `test_dry_run_deletes_nothing_and_lists_old_files` and `test_cli_dry_run_flag`.
  - The tests cover both the library path (`cleanup(..., dry_run=True)`) and the CLI path (`main([... "--dry-run"])`).
- **Edit hygiene.** I only worked on a copy. Nothing in the run directory was modified.

## Findings

None at Falsifying, Overreaching, or Gap level. One Note:

**Note.** The entry does not say that "old" means older than 30 days, from the hardcoded `AGE_DAYS = 30` (cleanup.py:6), and that only `*.log` files directly in the directory are considered, not subdirectories (cleanup.py:11). This is not a defect, because the flag's claim is about what would be deleted, and that is the same set a real run deletes. A reader may still want the scope stated. If you choose to add it, the sentence would be: "...prints the `*.log` files older than 30 days that would be deleted and deletes nothing." I did not test subdirectories, since that is existing behavior, not part of 1.4.0.

## Limits of my examination

- I ran Linux, Python via pytest, and one small directory. I did not test permission errors, symlinks, or Windows.
- I did not check whether 1.4.0 is the correct version number or whether other changes shipped in 1.4.0 that are missing from the changelog. There is no version file or history in the run directory, so I could not check this ("Unverifiable by me": I would need the git history or a version field).
- "Prints" means stdout in the CLI. I observed this in the CLI run and in the `capsys` test.

## Verdict

- Claim 1, flag accepted: **Supported.**
- Claim 2, prints would-be-deleted files and deletes nothing: **Supported** (rerun by hand, plus tests).
- Claim 3, "Covered by `tests/test_cleanup.py`": **Supported**, as shown by two mutations that the tests caught.
- Version number and completeness of the 1.4.0 entry: **Unverifiable by me.**

Ledger of my own errors: none so far.
