Review of the 1.4.0 entry in CHANGELOG.md

The entry under review is one bullet:
"`cleanup.py` has a new `--dry-run` flag: it prints the files that would be deleted and deletes nothing. Covered by `tests/test_cleanup.py`."

I ran everything in a scratch copy at /tmp/rv_3c90. The run directory was not modified.

Verdicts by claim

1. "`cleanup.py` has a `--dry-run` flag": Supported.
   - What I did: ran `python cleanup.py --help`, then made a scratch directory with old.log (40 days old) and new.log (1 day old) and ran `python cleanup.py demo --dry-run`.
   - What happened: help shows `--dry-run   show what would be deleted wihtout deleting`. The dry run printed `would delete demo/old.log`.

2. "prints the files that would be deleted": Supported.
   - Same run. Only old.log was listed. new.log was not, which matches the test at tests/test_cleanup.py line 26.

3. "deletes nothing": Supported.
   - After the dry run, `ls demo` showed both old.log and new.log. The following real run (no flag) removed old.log and left new.log. So the dry run did delete nothing.
   - Code: os.remove is reached only in the else branch of cleanup() (cleanup.py lines 21-24).

4. "Covered by tests/test_cleanup.py": Supported.
   - What I did: ran `pytest -v tests/`, then two mutations on the scratch copy.
   - What happened: 3 passed. M1 (main passes dry_run=False, so the CLI ignores the flag): test_cli_dry_run_flag fails. M2 (the dry-run branch in cleanup() disabled): test_dry_run_deletes_nothing_and_lists_old_files and test_cli_dry_run_flag fail. Restored copy passes 3/3.
   - So the tests would catch a broken flag at either the CLI wiring or the function.

5. "new": Unverifiable by me.
   - The directory has no git history and no earlier cleanup.py or changelog entries to compare against. I cannot tell whether the flag predates 1.4.0.
   - What would settle it: the git history of cleanup.py, or the 1.3.x changelog entries, showing the flag was absent before.

6. "1.4.0" as the release number: Unverifiable by me.
   - There is no version file (setup.py, pyproject.toml, __version__) in the directory. Nothing here contradicts the label, but nothing confirms it.

What held up

- The flag exists, is wired through main() to cleanup() (cleanup.py line 34), and behaves as the entry says in both the CLI and the function.
- The dry run is read-only: find_old() only calls stat(), and nothing is removed.
- The three tests pass, and each one fails when the feature is broken, so "Covered by tests/test_cleanup.py" is a real statement about coverage.

Findings

- No Falsifying or Overreaching findings. Every claim in the entry is stated at or below the level of the evidence.
- Gap, limited to the word "new" (claim 5). Closing it needs the git history or prior changelog. This does not block the entry's content.

- The only open item is whether the flag is new, and I cannot test that from this directory.
