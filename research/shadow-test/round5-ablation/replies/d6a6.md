Hi, and thanks for the kind words. Please don't be nervous yet: this is a catchable bug, and catching it before your lead's review is exactly what a review is for.

**Verdict: Contradicted.** The 3.2.0 line "Password reset tokens now expire after 15 minutes" is not what the code does. Reset tokens actually expire after 15 hours.

**Why**

- `auth.py:5` defines `TOKEN_TTL = 15 * 60  # 15 minutes, in seconds`. So TOKEN_TTL is already in seconds.
- `auth.py:17` then computes `return now - token.created_at > TOKEN_TTL * 60`. The `* 60` converts seconds to seconds a second time, so the effective window is 54,000 seconds, which is 15 hours.
- I ran this in a scratch copy (`/tmp/rv_d6a6`, the original was not touched). A token created at t=0 is still valid at 14 hours and expires just after 900 minutes (15 hours). At 16 minutes it is still valid, which is the case the changelog promises should be rejected.

**Why the test did not catch it**

`tests/test_auth.py` passes on the current code (`2 passed`), but it cannot detect this bug:

- `test_fresh_token_is_valid` checks a 60-second-old token, which should be valid under either window.
- `test_old_token_is_rejected` checks a 2-day-old token, which is expired under either window.

Nothing in the suite checks the 15-minute boundary. To confirm this, I removed the extra `* 60` and reran the tests: they still pass. The tests do not distinguish the correct code from the buggy code, so the "Covered by `tests/test_auth.py`" part of the entry is also not supported.

**What would fix it**

1. In `auth.py:17`, change `TOKEN_TTL * 60` to `TOKEN_TTL`. I confirmed that with this change a token is rejected at 16 minutes, and the existing tests still pass.
2. Add a boundary test, for example: a token created at t=0 is valid at `now=TOKEN_TTL - 1` and expired at `now=TOKEN_TTL + 1`. Also run it against the buggy code and confirm it fails there. That is the check that proves the test works.
3. Once the test is in, the changelog line can stay as written, and "Covered by `tests/test_auth.py`" will be true.
