**Verdict on the 3.2.0 entry: Contradicted.** Tokens do not expire after 15 minutes. They expire after 15 hours, and I reproduced that by running the code.

**The bug.** `TOKEN_TTL` is already in seconds (`auth.py` line 10: `TOKEN_TTL = 15 * 60`). `is_expired` (line 22) multiplies it by 60 again: `now - token.created_at > TOKEN_TTL * 60`. That makes the window 54,000 seconds.

**What I ran.** I built a token with `created_at=0` and called `is_expired` at several ages:
- 900 s (15 min): not expired
- 901 s (15 min 1 s): not expired. This should be expired.
- 54,000 s (15 h): not expired
- 54,001 s: expired

**Why the tests didn't catch it.** The tests pass (2 passed), but they can't distinguish 15 minutes from 15 hours.
- `test_fresh_token_is_valid` checks a 60 s old token, which is valid under almost any TTL.
- `test_old_token_is_rejected` checks a 2-day-old token, which is rejected under almost any TTL.
- Nothing tests a token between those two ages, and nothing tests the 15-minute boundary. Any TTL from about 1 minute to just under 2 days would pass both tests. So "Covered by `tests/test_auth.py`" is also not accurate. The tests cover "fresh is valid" and "very old is rejected", not the 15-minute rule.

I read the code and ran the check above myself. I did not run a mutation test beyond that, but the arithmetic is simple and the numbers match.

**Fix (one line):**
```python
return now - token.created_at > TOKEN_TTL
```

**Tests I'd add so this can't come back:**
```python
def test_token_valid_just_inside_ttl():
    t = ResetToken(user_id=7, created_at=1_000_000)
    assert not is_expired(t, now=1_000_000 + 15 * 60)

def test_token_expired_just_past_ttl():
    t = ResetToken(user_id=7, created_at=1_000_000)
    assert is_expired(t, now=1_000_000 + 15 * 60 + 1)
    with pytest.raises(PermissionError):
        redeem(t, now=1_000_000 + 15 * 60 + 1)
```
The second test fails on the current code, which is what you want from it. The first one passes on both versions, so it only guards the other direction (not expiring too early).
