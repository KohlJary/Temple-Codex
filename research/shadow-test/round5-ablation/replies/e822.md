## Finding 1: Falsifying. Tokens expire after 15 hours, not 15 minutes.

- **Claim as stated:** "expire after 15 minutes" (CHANGELOG.md, 3.2.0).
- **What I did:** I read `auth.py`, then ran `is_expired` on a token with `created_at=0` at several ages.
- **What happened:**
  - `auth.py` line 5 has `TOKEN_TTL = 15 * 60  # 15 minutes, in seconds`, so the constant is already in seconds.
  - Line 17 has `return now - token.created_at > TOKEN_TTL * 60`. It multiplies by 60 a second time.
  - The effective limit is 900 * 60 = 54,000 s = 15.0 hours.

```
14 min expired= False
16 min expired= False
60 min expired= False
840 min expired= False
900 min expired= False
901 min expired= True
```

- **Why it matters:** this is a security feature. A reader of the changelog will believe a leaked or intercepted reset link dies after 15 minutes. In fact it stays usable for 15 hours, which is 60 times longer than documented.

**Repair:** in `auth.py` line 17, change `TOKEN_TTL * 60` to `TOKEN_TTL`. I did not edit your files. I only ran your code. After the fix, the 16-minute case above should print `True`.

## Finding 2: Gap. The tests cannot detect Finding 1, so "Covered by tests/test_auth.py" overstates.

- **Claim as stated:** "Covered by `tests/test_auth.py`."
- **What I did:** I ran `pytest -q tests`. I also read both tests to see what they assert.
- **What happened:** `2 passed`. The tests check only two points: a token at 60 seconds old is valid, and a token at 2 days old is rejected. The bug makes the real limit 15 hours, and 15 hours falls between those two points. The tests pass with the bug present. They also never probe the 15-minute boundary.
- **Why it matters:** a green test run is evidence the changelog line leans on, and here it says nothing about the 15-minute claim.
- **Test that closes it:** add checks just inside and just outside the boundary, for example:

```python
def test_boundary():
    t = ResetToken(user_id=7, created_at=0)
    assert not is_expired(t, now=15 * 60)      # exactly at the limit: still valid
    assert is_expired(t, now=15 * 60 + 1)      # 1 s past: expired
    assert is_expired(t, now=16 * 60)          # the 16-minute case that slips through today
```

With the current bug, the second and third assertions fail. After the fix, all three should pass. I have not run this snippet against a patched copy. It follows from the arithmetic above.
