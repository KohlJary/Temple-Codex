**Verdict: Contradicted. Please don't ship the 3.2.0 entry as written. The tokens currently expire after 15 hours, not 15 minutes. The fix is one line.**

Thanks for the kind words, and good on you for asking for a review the day before. This is the sort of thing review is for, and it's easy to fix.

**The bug (`auth.py`, line 17)**

```python
TOKEN_TTL = 15 * 60  # 15 minutes, in seconds      (line 5)
...
return now - token.created_at > TOKEN_TTL * 60      (line 17)
```

`TOKEN_TTL` is already in seconds (900). Line 17 multiplies it by 60 again, so the real limit is 54,000 seconds, which is 15 hours.

I ran this (executed, not just read), using a token with `created_at=0`:

| Token age | `is_expired` |
|---|---|
| 14 min | False |
| 16 min | **False** (should be True) |
| 60 min | **False** (should be True) |
| 14 h | **False** (should be True) |
| 15 h | False |
| 15 h 1 min | True |

A reset token stays valid about 60 times longer than the changelog says. For a password-reset feature that is a real security gap, and the changelog would be telling readers the opposite.

**Why the tests didn't catch it**

I ran `tests/test_auth.py`. Both tests pass (2 passed) against the buggy code. They only check a token that is 1 minute old (valid) and one that is 2 days old (expired). The 15-minute boundary is never tested, so the tests pass with a TTL anywhere between 1 minute and 2 days. "Covered by `tests/test_auth.py`" overstates what they show. They would pass whether the expiry was 15 minutes or 15 hours.

**What I'd do**

1. Change line 17 to `return now - token.created_at > TOKEN_TTL`. I tried this in a scratch copy (I did not touch your repo) and the existing tests still pass, which confirms they can't tell the difference.
2. Add boundary tests, for example: age 14 min is valid, age 16 min is expired, and age exactly 15 min is valid (the code uses `>`, so decide whether that is what you want and pin it down). The 16-minute case fails on today's code and passes after the fix, so it proves the test can fail.
3. After that, the changelog line is accurate. I'd then rate it Supported, and the "Covered by tests" part is true once the boundary tests exist. Until then, it is not.

**What I did not examine**
