Review of the 1.4.0 entry in CHANGELOG.md

The entry makes three claims. I ran the code and tests in a scratch copy at /tmp/rv_ce35. I did not modify the run directory.

**Claim 1: "`cleanup.py` has a new `--dry-run` flag"**
Verdict: Supported.
- What I did: read `cleanup.py` (argparse at line 31, `cleanup()` at lines 17-25). Ran `python cleanup.py <dir> --dry-run` against a temp directory with one 40-day-old `.log` and one 1-day-old `.log`.
- What happened: exit 0, stdout `would delete /tmp/tmpslpci0y7/old.log`. The old file still existed afterward.
- Also checked: `--help` lists `--dry-run`.

**Claim 2: "it prints the files that would be deleted and deletes nothing"**
Verdict: Supported.
- What I did: read lines 20-24, where the dry-run branch prints and the `os.remove` call sits only in the else branch. Ran the same temp-directory check, then a real run without the flag.
- What happened: the real run exited 0, deleted `old.log`, and left `new.log` in place. The dry run deleted nothing.

**Claim 3: "Covered by `tests/test_cleanup.py`"**
Verdict: Supported.
- What I did: ran `python -m pytest -q` in the scratch copy.
- What happened: `3 passed in 0.02s`.
- What the tests cover: `test_dry_run_deletes_nothing_and_lists_old_files` checks that nothing is deleted and that the old file is listed and the new one is not. `test_cli_dry_run_flag` checks the CLI path and that the file still exists.

**Claim 4: "new"**
Verdict: Unverifiable by me.
- Why: the run directory has no git history, no earlier release, and no version string in the code. I cannot confirm the flag was absent in 1.3.x.
- What would settle it: the 1.3.x tag or release, plus a diff showing `--dry-run` was added in 1.4.0.

**What held up**
- The flag exists and behaves as the entry says, verified by running it on real files and by the three passing tests.
- The dry-run path cannot delete: the `os.remove` call is only reachable when `dry_run` is false.
- The real-delete path still works, and it deletes only files older than 30 days.

Nothing here is falsifying or overreaching. The one gap is the word "new," which needs the prior release to check.
