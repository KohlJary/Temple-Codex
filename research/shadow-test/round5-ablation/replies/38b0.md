**Verdict: Contradicted.** The changelog says reset tokens expire after 15 minutes. In the code they expire after 15 hours.

**The bug** (`auth.py`, line 22 in the file; `is_expired`):

    return now - token.created_at > TOKEN_TTL * 60

`TOKEN_TTL` is already in seconds (`15 * 60` on line 10). Multiplying by 60 again makes the window 54,000 seconds, which is 15 hours.

**What I ran** (copy of your code in /tmp/rv_38b0, your directory untouched), with a token created at t=0:

- 901 s (15 min + 1 s): expired = False
- 3,600 s (1 hour): expired = False
- 53,999 s (about 15 h): expired = False
- 54,001 s: expired = True

So a token stays usable for 60x longer than the changelog says. For a password-reset token that is a real security difference, which is why I would not let the entry go out as written.

**Why your tests didn't catch it:** the entry says "Covered by `tests/test_auth.py`". The 2 tests pass (I ran them), but they only check a token at 60 seconds (valid) and at 2 days (expired). Both results are the same whether the TTL is 15 minutes or 15 hours, so the tests cannot fail on this bug. Nothing tests the 15-minute boundary, so "covered" is not supported either. This was a hard one to spot, since the tests are green.

1. In `auth.py`, change line 22 to `> TOKEN_TTL`.
