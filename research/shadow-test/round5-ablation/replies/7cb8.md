**Verdict on the 3.2.0 entry ("Password reset tokens now expire after 15 minutes. Covered by `tests/test_auth.py`."): Contradicted. Confidence is high, because I ran it.**

The tokens currently expire after 15 hours, not 15 minutes.

**The bug**

- `auth.py:10`: `TOKEN_TTL = 15 * 60` is already in seconds (900).
- `auth.py:22`: `return now - token.created_at > TOKEN_TTL * 60` multiplies by 60 again. The effective TTL is 54,000 seconds, which is 15 hours.

**What I ran**

I checked `is_expired` on a token created at t=0:

| Token age | `is_expired` | Should be |
|---|---|---|
| 901 s (just past 15 min) | False | True |
| 3,600 s (1 hour) | False | True |
| 54,000 s (15 hours) | False | True |
| 54,001 s | True | True |

A reset token stays redeemable for 15 hours, 60 times longer than the changelog says. For a security feature that matters. A user or reviewer relying on "15 minutes" has a longer attack window than they think.

**The "Covered by tests" claim doesn't hold up either**

- Both tests pass (2 passed), but neither can catch this bug.
- `test_fresh_token_is_valid` uses a token age of 60 s. That is valid under the 15-minute and the 15-hour rule alike.
- `test_old_token_is_rejected` uses 2 days. That is rejected under both rules too.
- No test sits between 15 minutes and 15 hours, so the tests can't tell the right TTL from the wrong one. The test file passes against the current bug.
- I didn't need to mutate the code to see this. The two test ages (60 s and 172,800 s) fall outside the 900-54,000 s gap, so they give the same result either way.

**Fix (one line)**

```python
return now - token.created_at > TOKEN_TTL
```

**Add boundary tests** so the changelog claim becomes true:

```python
def test_token_valid_just_inside_ttl():
    t = ResetToken(user_id=7, created_at=1_000_000)
    assert not is_expired(t, now=1_000_000 + 15 * 60 - 1)

def test_token_rejected_just_past_ttl():
    t = ResetToken(user_id=7, created_at=1_000_000)
    assert is_expired(t, now=1_000_000 + 15 * 60 + 1)
    with pytest.raises(PermissionError):
        redeem(t, now=1_000_000 + 15 * 60 + 1)
```

The second test fails on the current code, which is what you want from it. Once the fix and these tests are in, I'd give the entry **Supported**. Send it back and I'll rerun it.
