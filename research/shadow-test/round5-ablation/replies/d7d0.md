# Review of CHANGELOG.md, 1.4.0 entry

Claim as stated (CHANGELOG.md, 1.4.0): "`cleanup.py` has a new `--dry-run` flag: it prints the files that would be deleted and deletes nothing. Covered by `tests/test_cleanup.py`."

Restated as three testable sentences:
1. `--dry-run` exists on the CLI.
2. With it, the old `*.log` files are printed and nothing is deleted.
3. `tests/test_cleanup.py` covers this behavior.

## What held up (ran it)

- Ran `pytest` on `tests/`: 3 passed.
- Ran the CLI on a scratch dir with `old.log` (mtime 40 days ago) and `new.log` (now).
  - `cleanup.py d --dry-run` printed `would delete d/old.log`, exited 0, and both files were still present afterward. It did not list `new.log`.
  - `cleanup.py d` without the flag removed `old.log` and left `new.log`. So the flag changes behavior, and the non-dry path still deletes.
  - `--help` lists `--dry-run`.
- Read the tests:
  - `test_dry_run_deletes_nothing_and_lists_old_files` checks the library path: files survive and the output names the old file and not the new one.
  - `test_cli_dry_run_flag` checks the actual `--dry-run` argument through `main()`: file survives and "would delete" is printed.
  - `test_real_run_deletes_only_old` guards the opposite direction.
  So "covered by tests" is accurate, including the CLI flag itself.

## Findings

None at Falsifying, Overreaching, or Gap level.

- **Note:** "the files that would be deleted" means `*.log` files older than the fixed 30-day threshold, non-recursive. This is what the code does for real runs too, so the dry-run preview matches the real run. The changelog does not need to say more.

I did not examine anything beyond this entry: other platforms, symlinks, or unreadable files were not tried. The claim does not reach those.

## Verdict

- Claim 1 (flag exists): **Supported.**
- Claim 2 (prints would-be-deleted files, deletes nothing): **Supported.** Confirmed by rerun on one scratch directory and by the tests.
- Claim 3 (covered by tests/test_cleanup.py): **Supported.**

The entry can ship as written.
