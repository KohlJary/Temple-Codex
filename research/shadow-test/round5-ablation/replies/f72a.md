## Finding 1: the expiry window is 15 hours, not 15 minutes (Falsifying)

**Claim as stated:** CHANGELOG.md, 3.2.0: "Password reset tokens now expire after 15 minutes."

**What I did:** Read `auth.py` and `tests/test_auth.py`. Then, in a scratch copy at /tmp/rv_f72a (the run directory was not modified), I ran the tests and probed `is_expired` directly with a token created at t=0.

**What happened:**
- `auth.py` line 5: `TOKEN_TTL = 15 * 60  # 15 minutes, in seconds`
- `auth.py` line 17: `return now - token.created_at > TOKEN_TTL * 60`
- Probe output: `TOKEN_TTL = 900 effective window (s) = 54000 = 15.0 hours`
- Probe, with `now` given in minutes after creation: `14 min -> expired: False`, `60 min -> expired: False`, `899 min -> expired: False`, `901 min -> expired: True`. The flip happens at 900 minutes (15 hours), not at 15 minutes.
- `pytest`: `2 passed`

**Why it matters:** `TOKEN_TTL` is already in seconds, so multiplying by 60 again converts 15 minutes into 15 hours. A reset token would be redeemable for 15 hours after it is issued. For a security feature, that is the exact opposite of what the changelog promises, and a reader would reasonably believe the window is much shorter than it is.

The test does not catch this, and that is a separate issue. `test_fresh_token_is_valid` checks a token that is 60 seconds old, which is inside both the intended and the actual window. `test_old_token_is_rejected` checks a token that is 2 days old, which is outside both. Neither test sits at the 15-minute boundary, so the suite passes with the bug in place. That makes the "Covered by `tests/test_auth.py`" sentence a Gap as well: the tests exist, but they do not reach the claim.

**Repair (one token):** change line 17 to
`return now - token.created_at > TOKEN_TTL`
In my scratch copy, with that change, the probe gives `899 s -> False`, `900 s -> False`, `901 s -> True`, and `3600 s -> True`, and both existing tests still pass. Note that I did not run that change in the actual run directory, which is yours to edit.

**Suggested test to add:** a boundary test that is both exact and would have caught this:

```python
def test_token_expires_at_15_minutes():
    t = ResetToken(user_id=7, created_at=1_000_000)
    assert not is_expired(t, now=1_000_000 + 15 * 60)
    assert is_expired(t, now=1_000_000 + 15 * 60 + 1)
```

Run against the current code, it fails on the second assert (the token is not yet expired at 15 minutes plus 1 second). Against the fixed code, it passes. That is the test I would want to see before believing the changelog line.

**Changelog wording:** once the fix and the boundary test are in, "Password reset tokens now expire after 15 minutes. Covered by `tests/test_auth.py`" stands as written. Until then, I would hold that line.
