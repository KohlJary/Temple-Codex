**Finding 1: the 15-minute expiry is actually 15 hours (Falsifying)**

- **Claim as stated:** CHANGELOG.md line 5: "Password reset tokens now expire after 15 minutes."
- **What I did:** Read `auth.py` line 5 and line 17. Copied the run to a scratch directory and imported `is_expired` from the copy, with `created_at=1_000_000`, probing several ages.
- **What happened:**
  - `auth.py:5`: `TOKEN_TTL = 15 * 60  # 15 minutes, in seconds`
  - `auth.py:17`: `return now - token.created_at > TOKEN_TTL * 60`
  - Probe output: `TOKEN_TTL = 900`, then `16 min: is_expired=False`, `1 hour: is_expired=False`, `14 hours: is_expired=False`, `15 hours +1 min: is_expired=True`, `16 hours: is_expired=True`
- **Why it matters:** `TOKEN_TTL` is already in seconds, so line 17 multiplies by 60 a second time. The effective lifetime is 54,000 seconds, or 15 hours. A reset token is a security credential, and this would let one stay redeemable for 60 times the documented window. Please don't merge or publish 3.2.0 with this as written.
- **Severity:** Falsifying. The claim is untrue for the code as it stands.

**Finding 2: the test does not cover the 15-minute behavior (Falsifying, for the "Covered by" sentence)**

- **Claim as stated:** CHANGELOG.md line 5: "Covered by `tests/test_auth.py`."

- **Why it matters:** A reader would reasonably believe the suite would catch a wrong expiry. It would not have caught this one. The green run is the reason the bug got past the tests.
- **Severity:** Falsifying for this sentence. The test file as it stands does not reach the claim.

**Repair (I verified both on the scratch copy)**

1. In `auth.py` line 17, change `TOKEN_TTL * 60` to `TOKEN_TTL`. That's the whole code fix.
2. Add boundary tests. This is what I ran, and it fails on the current code:

```python

    t = ResetToken(user_id=7, created_at=1_000_000)
```
