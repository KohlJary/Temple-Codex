Review of the 1.4.0 entry in CHANGELOG.md

Summary: both claims in the entry hold. I found no falsifying or overreaching claims.

Claims examined

C1. "`cleanup.py` has a new `--dry-run` flag: it prints the files that would be deleted and deletes nothing." (CHANGELOG.md, line 3)
C2. "Covered by `tests/test_cleanup.py`." (same line)

What I did and what happened

1. Ran the suite on a scratch copy at /tmp/rv_4cf0 (I did not touch the run directory, so no caches were written there):
   python3 -m pytest -p no:cacheprovider -q -v tests/test_cleanup.py
   Output: "collected 3 items ... 3 passed in 0.02s"
   The three tests are test_dry_run_deletes_nothing_and_lists_old_files, test_real_run_deletes_only_old, and test_cli_dry_run_flag.

2. Mutation check A: in the scratch copy, I made cleanup() ignore dry_run (set dry_run = False at the top of the function).
   Output: "2 failed, 1 passed". The failures were test_dry_run_deletes_nothing_and_lists_old_files and test_cli_dry_run_flag. So the dry-run tests do detect a real deletion.

3. Mutation check B: in the scratch copy, I made main() call cleanup() without passing a.dry_run.
   Output: "1 failed, 2 passed". The failure was test_cli_dry_run_flag. So the CLI wiring is covered by a test.

4. Ran the real CLI on a demo directory with one 40-day-old old.log and one new new.log:
   python3 cleanup.py DIR --dry-run
   Output: "would delete /tmp/rv_4cf0/demo.quYA/old.log", exit 0. Afterwards the directory still held both files.
   python3 cleanup.py DIR (no flag)
   Exit 0, and the directory afterwards held only new.log. So the flag is the only difference, and it does what the entry says.

5. Read cleanup.py lines 17-25. In the dry-run branch, the only action is a print. os.remove is in the else branch only.

Claim verdicts

C1: Supported. The dry run prints one "would delete <path>" line per old *.log file and calls no os.remove. The CLI run confirmed this with real files.
C2: Supported. tests/test_cleanup.py exercises the dry-run path directly (test 1), through the CLI (test 3), and the non-dry-run path as a contrast (test 2). Both mutation checks show the tests fail when the feature is broken.

Findings

None. No claim is untrue, and no claim goes beyond what I checked.

What held up (checked, and sound)

- The 3 tests pass on the code as it stands.
- The dry-run tests fail under a deliberately broken cleanup(), so they test the real behavior and do not just pass vacuously.
- The CLI wiring from --dry-run to dry_run=True is covered by test_cli_dry_run_flag.
- The real CLI behaves as the entry describes, shown above with real files.

Scope note (not a claim in the entry)

The dry-run flag applies to the same selection as normal runs: *.log files older than AGE_DAYS (30). The entry does not claim anything about other file types or ages, so this is not a finding.
