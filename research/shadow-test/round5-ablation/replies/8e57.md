**Verdict on "Password reset tokens now expire after 15 minutes. Covered by `tests/test_auth.py`": Contradicted.** The code expires tokens after 15 hours, not 15 minutes. I would not let this go to your lead as written. It's a one-character fix, though, and you have time to do it before tomorrow morning.

**The bug (executed, not just read)**
- `auth.py:5` sets `TOKEN_TTL = 15 * 60`, which is already in seconds (900).
- `auth.py:17` then computes `now - token.created_at > TOKEN_TTL * 60`. That multiplies by 60 a second time, so the cutoff is 54,000 seconds, or 15 hours.
- I ran `is_expired` against a token created at t=0:
  - 901 s (just past 15 min): `False`, so it is still valid
  - 3600 s (1 hour): `False`
  - 50400 s (14 hours): `False`
  - 53999 s: `False`
  - 54001 s (15 h): `True`
- A reset token that is meant to live for 15 minutes is therefore usable for 15 hours, which is 60 times longer. For a security feature, that is the property the changelog says you have.

**The test claim: "Covered by `tests/test_auth.py`": Contradicted as worded.**
- `pytest` passes (2 passed), but the tests can't catch this bug.
- `test_fresh_token_is_valid` checks a token at 60 seconds. It would pass with a TTL of 2 minutes or 2 years.
- `test_old_token_is_rejected` checks a token at 2 days. That is expired under both 15 minutes and 15 hours, so it passes with the bug.
- Nothing tests the boundary, which is the 15-minute behavior the changelog claims. I did not need to mutate the code to see this, because the bug is in the code and the suite is green with it.

**Suggested fix (I did not modify your repo; I tested this in a scratch copy)**

def test_token_valid_just_inside_ttl():

def test_token_expired_just_past_ttl():
