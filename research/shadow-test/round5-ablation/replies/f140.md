# Review of CHANGELOG.md, 1.4.0 entry

## Claim, restated narrowly

Entry: "`cleanup.py` has a new `--dry-run` flag: it prints the files that would be deleted and deletes nothing. Covered by `tests/test_cleanup.py`."

Testable sentences:
1. `python cleanup.py DIR --dry-run` prints one line per file that a real run would delete, and removes no files.
2. `tests/test_cleanup.py` has tests that exercise that path.

## What I did

- Read `cleanup.py`, `tests/test_cleanup.py`, `CHANGELOG.md`.
- Ran `python -m pytest -q tests`: `3 passed in 0.05s`.
- Ran the real CLI in a scratch dir (/tmp/rv_f140) with `a.log` (40 days old), `b.txt` (40 days old), `c.log` (new):
  - `cleanup.py d --dry-run` printed `would delete d/a.log`, exit 0, and `ls d` still showed `a.log b.txt c.log`.
  - `cleanup.py d` (no flag) removed only `a.log`, leaving `b.txt c.log`.
  - A second dir with only an old `x.log`: `--dry-run` printed `would delete e/x.log`, and `x.log` was still there afterward.

## What held up

- **Behavior claim.** The flag exists, prints the would-be-deleted files, and deletes nothing. Confirmed by running the CLI, not just by reading.
- **Parity with a real run.** The dry-run list matched what the real run then deleted in my scratch case. Both go through the same `find_old`, so they cannot drift apart.
- **Test coverage claim.** `test_dry_run_deletes_nothing_and_lists_old_files` checks the function path, including that a new file is not listed. `test_cli_dry_run_flag` goes through `main(["--dry-run"])`, so the argparse wiring is covered. `test_real_run_deletes_only_old` is a useful control. All 3 pass.
