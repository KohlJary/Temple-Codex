Review of the 1.4.0 entry in CHANGELOG.md

Verdict on each claim

1. Claim as stated: "`cleanup.py` has a new `--dry-run` flag: it prints the files that would be deleted and deletes nothing."
   Verdict: Supported.
   What I did: Copied the directory to /tmp/rv_783f and ran the CLI on a scratch directory holding two old .log files (40 and 35 days), one new .log file (2 days), and one old .txt file (90 days). Ran with --dry-run, then without it.
   What happened: The dry run printed "would delete demo/a.log" and "would delete demo/b.log" and exited 0. Afterwards all four files were still present. The real run deleted a.log and b.log, leaving c.log and keep.txt.
   Why it matters: This is the behavior the entry promises. The .txt file is correctly ignored because the code only globs *.log.

2. Claim as stated: "Covered by `tests/test_cleanup.py`."
   Verdict: Supported.
   What I did: Ran `python3 -m pytest -v tests/test_cleanup.py` in the scratch copy. Then I made three mutants of cleanup.py in scratch copies and reran the tests on each:
   - mutA: deletes even when dry_run is set.
   - mutB: main() passes dry_run=False and ignores the flag.
   - mutC: dry_run prints the line and also deletes the file.
   What happened: All 3 tests passed on the original code. mutA and mutC each failed two tests (test_dry_run_deletes_nothing_and_lists_old_files and test_cli_dry_run_flag). mutB failed test_cli_dry_run_flag.
   Why it matters: The tests cover the dry-run path and would catch the main ways the flag could break.

3. Claim as stated: the flag is "new" in 1.4.0.
   Verdict: Unverifiable by me.
   What I did: Looked at the scratch copy of the run directory. It holds only CHANGELOG.md, cleanup.py, and tests/test_cleanup.py. There is no git history and no earlier release.
   What happened: I cannot see what 1.3.x shipped, so I cannot confirm that the flag is new rather than a change to an existing flag.
   Why it matters: If the flag already existed, "new" is wrong. Checking the previous tag or the prior release's cleanup.py would settle it.

What I ran versus what I only read

- Ran: the 3 existing tests, the CLI on a scratch directory with both --dry-run and the real run, and the three mutants listed above.
- Read: CHANGELOG.md, cleanup.py, and tests/test_cleanup.py in full.

What held up

- The dry-run branch in cleanup() prints "would delete" for each old file and skips os.remove. The real-run branch removes only old .log files.
- main() forwards a.dry_run to cleanup(). The argparse flag is registered with action="store_true" and the help text matches what the flag does.
- find_old() selects files by mtime older than 30 days, and the tests set mtimes explicitly, so the age boundary is not in doubt for these cases.
- The changelog entry is brief and accurate. It names the flag, the behavior, and the test file, and it claims nothing beyond those.

Gaps and notes

- Gap (for claim 3 only): the "new" wording needs the prior release to check. Nothing in this run directory settles it. No change to the entry is needed if the flag is in fact new.
- No findings of severity Falsifying or Overreaching.
- Note: the help text in cleanup.py says "wihtout." It is a typo in user-visible text. You did not ask for style comments, so I have not counted it as a finding.

Questions

- Does 1.3.x already have a --dry-run flag, or a similar option? That answer decides claim 3.
