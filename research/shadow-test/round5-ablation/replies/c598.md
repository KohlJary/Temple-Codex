**Verdict: Contradicted.** The 3.2.0 line says reset tokens expire after 15 minutes. The code expires them after 15 hours, and the test suite passes anyway, so it doesn't catch this.

**The bug:** `auth.py`, line 17:

```python
return now - token.created_at > TOKEN_TTL * 60
```

`TOKEN_TTL` is already in seconds (line 5: `TOKEN_TTL = 15 * 60  # 15 minutes, in seconds`). Multiplying by 60 again makes the window 54,000 seconds, which is 15 hours.

- Fix (`TOKEN_TTL * 60` changed to `TOKEN_TTL` on line 17): 16 min is now expired, 14 min is still valid. The two existing tests still pass.

**Why the tests don't catch it:**

- `test_old_token_is_rejected` uses a token that is 2 days old. A 15-hour window and a 15-minute window both reject that, so the test passes under either one.
- `test_fresh_token_is_valid` uses 60 seconds, which is valid under any window of at least a minute.
- I also removed the expiry check entirely (`return False`). One test failed in that case, so the suite does notice a missing expiry. It just can't tell 15 minutes from 15 hours.
