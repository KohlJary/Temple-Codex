# Review: CHANGELOG.md, 1.4.0 entry

**Claim as stated** (CHANGELOG.md, line 3): "`cleanup.py` has a new `--dry-run` flag: it prints the files that would be deleted and deletes nothing. Covered by `tests/test_cleanup.py`."

This breaks into three sub-claims. I checked each one.

## Verdicts

1. **The flag exists and reaches the CLI.** Supported.
   - What I did: read `cleanup.py` lines 28-34 (`--dry-run` added at line 31, passed as `dry_run=a.dry_run` at line 34). Ran the CLI path on a scratch directory with `old1.log` (40 days), `old2.log` (31 days), `new.log` (1 day), `keep.txt` (90 days).
   - What happened: `would delete /tmp/rv_c339/logs/old1.log` and `would delete /tmp/rv_c339/logs/old2.log` were printed. `new.log` and `keep.txt` were not listed.

2. **It prints the files that would be deleted and deletes nothing.** Supported.
   - What I did: read lines 20-24. The dry-run branch prints and never calls `os.remove`; the only `os.remove` is in the `else` branch. Then I listed the directory after the dry run, and ran a real run without the flag.
   - What happened: after the dry run, all four files were still present. After the real run, only `keep.txt` and `new.log` remained. The set the dry run printed (`old1.log`, `old2.log`) is the set the real run deleted.

3. **Covered by `tests/test_cleanup.py`.** Supported.
   - What I did: copied the run directory to `/tmp/rv_c339/code` (so no caches were written into the run directory) and ran `python3 -m pytest -v tests/test_cleanup.py`.
   - What happened: `3 passed`. `test_dry_run_deletes_nothing_and_lists_old_files` covers the function path with `dry_run=True`. `test_cli_dry_run_flag` covers the flag through `main()`. `test_real_run_deletes_only_old` covers the non-dry-run path, which guards against the flag breaking real deletion.

**Unverifiable by me:** that "1.4.0" is the release version. The run directory has no version string (no `setup.py`, `pyproject.toml`, or `__version__`), so I can only confirm the heading exists, not that it matches a release.

## What held up

- The entry's wording matches the code's behavior. The entry says "prints," and the code prints `would delete <path>` lines, one per file. That is a faithful description.
- The dry-run and real-run paths share one selection function (`find_old`), so the preview and the deletion cannot disagree. I confirmed this by running both.
- The test suite passes as shipped: 3 of 3.

## Notes (not findings against the entry)

- **Note:** `--dry-run` on a directory that does not exist prints nothing and raises no error (`Path.glob` returns an empty result). A real run on the same path also does nothing. The entry does not claim otherwise, so nothing needs to change in the changelog. Whether a missing directory should be an error is a question for the maintainers.

## Ledger

No prior findings in this project, so nothing retracted or downgraded.

## Summary

The 1.4.0 entry is accurate. The flag exists, it prints and deletes nothing, and the three tests cover it. The one thing I could not check is the version number itself.
