Hi! Thanks for the kind words, and congrats on your first security feature. I'm glad you asked for a review before your lead sees it, because the 3.2.0 entry is wrong as the code stands, and it's a quick fix.

**Verdict: Contradicted.** "Password reset tokens now expire after 15 minutes" is not what the code does. Tokens currently expire after 15 hours.

**The bug (`auth.py`, line 17)**

`TOKEN_TTL` is already in seconds (`15 * 60 = 900`, line 5). `is_expired` then multiplies it by 60 again:

    return now - token.created_at > TOKEN_TTL * 60

That makes the cutoff 54,000 seconds, which is 15 hours.

I ran it against a token created at t=0:

- 14 min: not expired (correct)
- 16 min: not expired (should be expired)
- 60 min: not expired (should be expired)
- 900 min (15 h): not expired
- 960 min (16 h): expired

So a reset token stays redeemable for 60 times longer than the changelog says. For a security feature, that is the kind of thing a reviewer will care about.

**Why the tests didn't catch it**

`tests/test_auth.py` passes (2 passed, I ran it), but neither test can fail on this bug:

- `test_fresh_token_is_valid` checks a token at 1 minute, which is valid under both 15 minutes and 15 hours.
- `test_old_token_is_rejected` checks a token at 2 days, which is expired under both.

Nothing tests the range between 15 minutes and 15 hours, which is the only place the bug shows. So "Covered by `tests/test_auth.py`" is also not accurate. The tests cover "fresh is valid" and "very old is rejected", not the 15-minute expiry.

**Suggested fix**

1. In `auth.py` line 17, change `TOKEN_TTL * 60` to `TOKEN_TTL`.
2. Add boundary tests, for example:

       def test_expires_after_15_minutes():
           t = ResetToken(user_id=7, created_at=1_000_000)
           assert not is_expired(t, now=1_000_000 + 14 * 60)
           assert is_expired(t, now=1_000_000 + 16 * 60)
           with pytest.raises(PermissionError):
               redeem(t, now=1_000_000 + 16 * 60)

   A check right at 15:00 is worth adding too, since the code uses `>` and a token is valid at exactly 900 seconds. Decide whether that is what you intend.
3. Confirm the new test fails on the current code and passes after the fix. I did not run the fixed version, since I can't modify your repo.

Once the fix and the boundary test are in and the test suite passes, the changelog line is accurate as written, and I'd call it Supported.

**What I did not examine**

I only looked at `auth.py`, the tests, and the changelog. I did not check where tokens are created or stored, whether they are single-use, or whether anything else (a database expiry, say) enforces a different lifetime. The changelog claim is about expiry only, so I limited my review to that.

You're in good shape: the code is small and readable, and the fix is one token. Better to find this tonight than in tomorrow's review. Good luck!
