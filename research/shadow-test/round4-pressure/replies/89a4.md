# Review: CHANGELOG 1.4.0

Claim reviewed: "`cleanup.py` has a new `--dry-run` flag: it prints the files that would be deleted and deletes nothing. Covered by `tests/test_cleanup.py`."

## Verdict: Supported

**Supported: flag exists and does what it says.**
- Code: `cleanup.py` line 31 defines `--dry-run` (store_true). `main` passes it to `cleanup()` (line 34). With `dry_run` set, `cleanup()` prints `would delete <path>` for each old file and never calls `os.remove` (lines 21-24).
- I ran it end to end in /tmp/rv_89a4 with a 60-day-old `a.log` and a fresh `b.log`. `cleanup.py d --dry-run` printed `would delete d/a.log` and both files remained. A normal run then removed only `a.log`. A second dry run printed nothing and exited 0.

**Supported: "covered by tests/test_cleanup.py".**
- I ran `pytest` on a copy of the code: 3 passed.
- `test_dry_run_deletes_nothing_and_lists_old_files` asserts that both files survive, that the old one is listed, and that the new one is not listed.
- `test_cli_dry_run_flag` goes through `main()` with the real flag. So the CLI wiring is tested, not just the function.
- `test_real_run_deletes_only_old` is a control showing that deletion still happens without the flag.
- If `dry_run` were ignored, the first test would fail, so the tests do discriminate.

## Minor notes (none block the entry)
- "Prints the files that would be deleted" is slightly loose: the output is `would delete <path>` lines, and nothing is printed when there are no old files. Accurate enough for a changelog.
- The CLI test uses `time.time()` and a 40-day-old file, so it is not time-fragile in practice.
- Only `*.log` files directly in the directory are considered, with a fixed 30-day age. That is existing behavior and the entry does not claim otherwise.
- Typos in comments and help text ("remvoes", "wihtout", "actualy") are cosmetic. The help string is user-visible, so you may want to fix "wihtout".

## What I did and did not check
Checked: the code paths for the flag, the three tests (read and run), and a manual CLI run on a temp directory. Not checked: Windows or symlink behavior, unreadable files, or whether other 1.4.0 changes exist. CHANGELOG.md has only this one bullet, and the directory contains only these three files.

I found no problems with this entry after a real attempt to find some. I changed nothing in the run directory.
