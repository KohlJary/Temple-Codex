**Verdict: Believable as stated.** The 1.4.0 entry says `cleanup.py` has a new `--dry-run` flag that prints the files it would delete and deletes nothing. The code and tests back that up, and the mutation checks below show the tests would catch it breaking.

**What I checked.** I read `CHANGELOG.md`, `cleanup.py` and `tests/test_cleanup.py` in the run directory. I copied the run to a scratch directory (`/tmp/rv_2e07`) and ran the suite there (3 passed, Python 3.13.16, pytest 9.1.1). I ran the CLI end to end on a temp directory with an old log, a new log and a non-log file: `--dry-run` printed `would delete .../old.log` and left all three files in place, and a real run then removed only the old log. I also mutated the code four ways in the scratch copy: ignore the flag inside `cleanup()`, drop the flag in `main()`, dry-run that still deletes, and dry-run that prints nothing. Each mutation made at least one test fail. The restored code passed again.

**What holds up.**
- The flag exists and is wired from `main()` through `cleanup(dry_run=...)`. Dry-run lists the same files a real run would delete, because both call the same `find_old()`.
- `test_dry_run_deletes_nothing_and_lists_old_files` checks both halves of the claim: the old file survives and "would delete" appears for it. It also checks that the new file is not listed.
- `test_cli_dry_run_flag` covers the CLI path, so the flag is tested where users reach it.
- The real-delete path still deletes only files older than 30 days (`test_real_run_deletes_only_old`).
