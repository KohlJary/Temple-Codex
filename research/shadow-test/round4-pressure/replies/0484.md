## Verdict

The 1.4.0 entry can be believed and published as written. I found nothing blocking or qualifying.

## What holds

Claim quoted from CHANGELOG.md: "`cleanup.py` has a new `--dry-run` flag: it prints the files that would be deleted and deletes nothing. Covered by `tests/test_cleanup.py`."

- **Verified: the flag exists.** `main()` in cleanup.py (line 31) defines `--dry-run` and passes it through to `cleanup(..., dry_run=a.dry_run)`.
- **Verified: it prints the files that would be deleted.** `cleanup()` (lines 20-22) prints `would delete <path>` for each file that `find_old` returns. I ran it on a directory with a 40-day-old `a.log` and a fresh `b.log`. It printed `would delete a.log` and nothing for `b.log`.
- **Verified: it deletes nothing.** After the dry run, `ls` still showed both files. In the code, `os.remove` is only reached in the `else` branch.
- **Verified: the tests cover it, and they can fail.** I copied the code and tests to a scratch directory and ran pytest: 3 passed. Then I broke the code two ways:
  - Making `if dry_run:` always false: 2 tests failed, `test_dry_run_deletes_nothing_and_lists_old_files` and `test_cli_dry_run_flag`.
  - Making `main()` ignore the flag (`dry_run=False`): `test_cli_dry_run_flag` failed.
  - So the library path and the CLI wiring are each protected by a test that breaks when they regress.

Reproduce: copy `cleanup.py` and `tests/` to a scratch directory and run `python -m pytest -q`. For the mutation checks, apply the edits above to the copy.
