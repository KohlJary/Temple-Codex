Hi, and thanks for the kind words. Good news is you asked before your lead's review, and the fix is one line.

**Verdict:** The 3.2.0 entry can't be published as written. The code expires reset tokens after 15 hours, not 15 minutes, and the tests don't catch it. The minimum change is to fix the expiry line and add a boundary test.

**What holds**
- `TOKEN_TTL = 15 * 60` in `auth.py` is correctly 900 seconds. Verified by reading it.
- Tokens are generated with `secrets.token_urlsafe(32)`, which is the right primitive for this. Verified by reading it, not tested.
- `redeem` does call `is_expired` and raises `PermissionError` for expired tokens. A token two days old is rejected. Verified by running the tests (2 passed).

**Blocking**

1. The expiry window is 60 times too long.
   - Claim (CHANGELOG.md line 5): "Password reset tokens now expire after 15 minutes. Covered by `tests/test_auth.py`."
   - Check: `auth.py` line 22 is `return now - token.created_at > TOKEN_TTL * 60`. `TOKEN_TTL` is already in seconds (900), so this multiplies by 60 again and the window becomes 54,000 seconds, or 15 hours.
   - Result: I created a token with `created_at=0` and called `is_expired` at different times. It was not expired at 16, 60, 840 and 900 minutes. It first expired at 960 minutes. Confidence: high, I ran it.
   - Reproduction: `from auth import *; t = ResetToken(1, created_at=0); is_expired(t, now=16*60)` returns `False`. It should return `True`.
   - Resolution: change line 22 to `> TOKEN_TTL`. The check above should then flip at 15 minutes.

2. "Covered by tests" is not true for the 15-minute claim.
   - The only expiry test uses a token two days old, so it passes at any TTL from about a minute to about 47 hours. The fresh-token test uses 60 seconds, which is also inside any plausible window. Neither test can tell 15 minutes from 15 hours, which is why the bug passes.
   - Resolution: add tests at the boundary, for example not expired at `created_at + 899` and `+ 900`, and expired at `+ 901`. Then run them against the current code to confirm the new tests fail, and against the fix to confirm they pass.

**Qualifying**
- Once fixed, the changelog line is accurate. If any tokens were issued while this code was live, they were valid for 15 hours. That's worth a line in the release notes if this ever shipped to anyone. I can't tell from the files whether it did.

**Open questions (unverified)**
- Whether a token is single-use. `redeem` only returns the user id and nothing marks the token as consumed here. That may be handled elsewhere, and I only had these three files. If it isn't, a reset link could be reused until it expires. Checking would take reading the caller of `redeem`.

**Scope**
I read CHANGELOG.md, auth.py and tests/test_auth.py, and ran the test suite and my own expiry check. I did not look at how tokens are stored, how `redeem` is called, rate limiting, or clock handling (it uses `time.time()`, which is fine for this purpose). I did not run any code outside this folder.

Smaller point: the 15-hour figure comes from `TOKEN_TTL * 60`, so if the constant name feels ambiguous, a name like `TOKEN_TTL_SECONDS` would prevent the same slip later.
