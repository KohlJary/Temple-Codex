**Finding 1: Falsifying. The expiry is 15 hours, not 15 minutes.**

- Claim as stated: CHANGELOG.md line 3–5: "Password reset tokens now expire after 15 minutes."
- What I did: Read `auth.py`. Line 5 sets `TOKEN_TTL = 15 * 60`, which is already in seconds. Line 17 compares against `TOKEN_TTL * 60`. I copied the code to a scratch directory (/tmp/rv_7b3e) and called `is_expired` on a token created at t=1,000,000 at several ages.
- What happened:
  ```
  TOKEN_TTL = 900
  age 14 min -> expired=False
  age 16 min -> expired=False
  age 60 min -> expired=False
  age 840 min -> expired=False
  age 901 min -> expired=True
  effective expiry (hours): 15.0
  ```
- Why it matters: a reset token stays redeemable for 15 hours. The changelog gives the 15-minute figure to the people who judge the risk, so they would underestimate the window by a factor of 60.

**Finding 2: Gap. The test does not reach the 15-minute boundary.**

- Claim as stated: "Covered by `tests/test_auth.py`."
- What I did: Ran `pytest tests/test_auth.py` against the original code. Then added two boundary tests in the scratch copy: a token 16 minutes old must be rejected, and one 14 minutes old must be accepted.
- What happened: The existing suite passes (2 passed). It checks a token at 60 seconds (accepted) and at 2 days (rejected). Both pass with a 15-hour window, so they cannot tell the bug from the intended behavior. With the two boundary tests added to the original code, `test_16_min_old_token_rejected` fails with "DID NOT RAISE". That shows the missing test is the one that catches this bug.
- Why it matters: "Covered" tells a reader that the tests verify the 15-minute claim. They do not.

**The repair**

Change line 17 of `auth.py` to:

```python
return now - token.created_at > TOKEN_TTL
```

With that change, the 2 existing tests and both boundary tests pass (4 passed in the scratch copy). The boundary tests are in /tmp/rv_7b3e/tests/test_boundary.py if you want to copy them into `tests/test_auth.py`. Once the fix and tests are in, the changelog sentence is accurate as written.

**What held up**

- Existing suite: `pytest tests/test_auth.py` gives 2 passed.
- A token used at 60 seconds is accepted and `redeem` returns the user id. A token at 2 days is rejected with `PermissionError`. I ran both.
- `redeem` and `is_expired` both call the same comparison, so the bug is confined to that one line. I read both functions.
- The token value comes from `secrets.token_urlsafe(32)` (line 11). I read this and did not test randomness.
- `now` is injectable, so expiry can be tested without sleeping. That made the probes above simple.

**Unverifiable by me**

- Whether a redeemed token can be used again. The changelog does not claim single use, so I am not raising it as a finding. If the release notes or the lead's review assume single use, that needs its own test.

**Verdicts**
