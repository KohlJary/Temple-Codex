**Verdict: Holds.**

**Claim tested.** CHANGELOG 1.4.0: "`cleanup.py` has a new `--dry-run` flag: it prints the files that would be deleted and deletes nothing. Covered by `tests/test_cleanup.py`." I read this narrowly as: with `--dry-run`, `cleanup.py` writes one `would delete <path>` line to stdout for each `*.log` file older than 30 days, and removes no files.

**What I checked.**
- Read `cleanup.py`. With `dry_run=True` the loop prints `would delete {f}` and skips `os.remove`. The `--dry-run` flag is wired through `main()` to `cleanup()`.
- Read `tests/test_cleanup.py`. It covers the three things the claim names: the function-level dry run (files left in place, the old file listed, the new file not listed), the real run (only the old file deleted, so the deletion path is still live), and the CLI flag end to end via `main([... "--dry-run"])`.
- Ran the suite in a scratch copy (`/tmp/rv_4932`): 3 passed.
- Checked the tests can fail. I made three mutants in the scratch copy:
  - A: dry run still deletes. Two tests fail.
  - B: dry run stops printing. Two tests fail.
  - C: CLI ignores `--dry-run`. The CLI test fails.
  So the tests would catch a broken dry run, not just pass whatever the code does.

**What I did not check.**
- The changelog's version number "1.4.0". The repo has no version file or tag, so I cannot confirm it.
- Behaviour on a real directory tree. I tested only with temp files created by the tests and one scratch run.

**Minor notes (below the line, none affect the verdict).**
- The `--dry-run` help string says "wihtout" (should be "without"). It is in the new flag's help text.
- The changelog does not say that only `*.log` files in the top level of the directory are considered (`glob`, not recursive). That was already true of the tool; it is not a claim about the new flag, so I am not counting it against the entry.
