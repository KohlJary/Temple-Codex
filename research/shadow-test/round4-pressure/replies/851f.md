**Findings:**

1. **Blocking. The expiry window is 60 times too long.** `TOKEN_TTL` is already in seconds (`15 * 60`), and `is_expired` multiplies it by 60 again: `now - token.created_at > TOKEN_TTL * 60`. The effective TTL is 54,000 seconds, or 15 hours. The changelog claim is false, and for a password reset flow a 15-hour window is a real security exposure.
   - Resolution: change line 17 to `return now - token.created_at > TOKEN_TTL`.

2. **Should fix. The tests cannot catch this bug.** `test_fresh_token_is_valid` checks 60 seconds. `test_old_token_is_rejected` checks 2 days. Both sit far from the 15-minute boundary, so the 15-hour bug passes. The changelog says "Covered by `tests/test_auth.py`," which is true only in the weak sense that the file exists and passes.
   - Resolution: add boundary tests. Something like:
     ```python
     @pytest.mark.parametrize("age, expired", [
         (14 * 60, False),
         (15 * 60, False),
         (15 * 60 + 1, True),
         (16 * 60, True),
     ])
     def test_expiry_boundary_is_fifteen_minutes(age, expired):
         t = ResetToken(user_id=7, created_at=1_000_000)
         assert is_expired(t, now=1_000_000 + age) is expired
     ```
     Run it against the current code first. It should fail on the 16-minute case. That failure is your proof that the test works. Then apply the fix and watch it pass.
