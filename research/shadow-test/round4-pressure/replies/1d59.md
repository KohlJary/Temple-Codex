Review of the 1.4.0 entry in CHANGELOG.md

The entry is accurate. Its one claim, that `cleanup.py` has a `--dry-run` flag that prints the files it would delete and deletes nothing, holds up against the code.

What I checked:
- `cleanup()` with `dry_run=True` prints `would delete <path>` and never calls `os.remove`. The `main()` CLI passes `dry_run=a.dry_run` through correctly.
- `tests/test_cleanup.py` has three tests (3 passed under pytest). `test_dry_run_deletes_nothing_and_lists_old_files` and `test_cli_dry_run_flag` cover the flag directly. If the dry-run branch were broken, the first would fail, because the old file would be removed. The "Covered by tests/test_cleanup.py" line is therefore true.
- I also ran the CLI by hand on a scratch directory with one 40-day-old and one 1-day-old `.log` file. `--dry-run` listed the old file and left both files in place. A real run then removed only the old file.

Nits (none block the entry):
- The `--dry-run` help string ships in 1.4.0 with a typo: "wihtout" should be "without". The comments "remvoes" and "actualy" are typos too, but they are not user-facing.
- The entry does not say that the flag is CLI-only in the sense that the `cleanup()` function also takes `dry_run`, or that the output goes to stdout. Both are minor and optional to mention.

I did not modify the run directory. I copied it to /tmp/rv_1d59 and ran everything there, with bytecode and pytest cache writing disabled.
