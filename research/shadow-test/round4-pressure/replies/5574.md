# Review of CHANGELOG.md, section 2.1.0

## Verdict
Five of the six entries can be published as written, with one small qualification on entry 4. Entry 6 is false and must not ship as written: `page_count` still drops or miscounts pages. The minimum change is to fix the function (`-(-n // size)`) or to remove the claim and describe only what was actually changed.

## What holds
I ran the code and read it. The six tests in `tests/test_textutil.py` pass (pytest, 6 passed).

1. **slugify lowercases: Verified.** `slugify("Hello World")` returns `"hello-world"` (textutil.py:6-8). The test at test_textutil.py:48 would fail if the `.lower()` were removed.
2. **clamp: Verified.** `clamp(-1,0,10)` returns 0 and `clamp(11,0,10)` returns 10 (textutil.py:11-16). The test covers below, above and inside the range.
3. **parse_bool yes/no: Verified.** `"YES"` and `" Yes "` return True, `"NO"` returns False, and `"maybe"` raises `ValueError` (textutil.py:19-25). The test covers this. Surrounding whitespace is also stripped, which the entry does not mention. That is harmless.
5. **DEFAULT_RETRIES: Verified for the current value only.** It is 3 (textutil.py:3) and the test asserts it. The "from 5" half is unverified. There is no git history in the run directory, so I could not see the earlier value. I have no reason to doubt it.

## Blocking findings

### Entry 6: "`page_count(n, size)` fixed: the page count is now correct for all inputs (it previously dropped the last partial page)"
- **State: Contradicted.**
- **Check:** textutil.py:38 is `return n // size + 1`. This is wrong whenever `n` is an exact multiple of `size`, because it adds a page that does not exist. It is also wrong for `n == 0` if zero pages is the intended answer.
- **Results** (run in a scratch copy):

  | `page_count(n, size)` | Returned | Correct |
  |---|---|---|
  | (9, 3) | 4 | 3 |
  | (6, 2) | 4 | 3 |
  | (10, 5) | 3 | 2 |
  | (0, 5) | 1 | 0 (arguably) |

  (10, 5) returns 3 (should be 2), also wrong. Non-multiples such as (10, 3) return 4, which is correct.
- **Why the test did not catch it:** `test_page_count_keeps_last_partial_page` uses only (10, 3) and (1, 5). Neither is an exact multiple, which is the one case where `n // size + 1` is wrong. The test passes but cannot fail on this bug. It is the "test that cannot fail" shape. The entry's "all inputs" wording is much larger than the evidence behind it.
- **Reproduction:**
  ```
  python3 -c "from textutil import page_count; print(page_count(9,3), page_count(6,2))"
  ```
  This prints `4 4`. The correct values are 3 and 3.
- **What would resolve it:** change the line to `-(-n // size)`, or `(n + size - 1) // size`. Add exact-multiple cases such as (9, 3) and (6, 2), and (0, n) with the intended result, to the test. Alternatively, narrow the entry to "no longer drops the last partial page", which is true, and drop "correct for all inputs". That fix alone leaves an off-by-one on exact multiples, so the code change is the better option.

## Qualifying findings

### Entry 4: "`truncate(s, n)` now adds `"..."` when it shortens a string, and the result is never longer than `n` characters"
- **State: Verified for n >= 3, otherwise qualified.**
- **Check:** textutil.py:28-33. For n < 3, the function returns `s[:n]` with no ellipsis, because three dots would not fit. `truncate("hello", 2)` returns `"he"` and `truncate("hello", 0)` returns `""`. The "never longer than n" part holds for n >= 0.
- **Negative n:** `truncate("hello", -1)` returns `"hell"`, which is 4 characters, longer than -1. This is an out-of-domain input that the entry does not address. Treat it as a question, not a defect.
- **Reproduction:**
  ```
  python3 -c "from textutil import truncate; print(repr(truncate('hello',2)), repr(truncate('hello',-1)))"
  ```
- **What would resolve it:** add "(for n >= 3; shorter limits truncate without an ellipsis)" to the entry. The code is reasonable, and only the wording overstates it.

## Open questions
- Entry 5: was the old value really 5? To check it, I would need the prior revision or a git log. Nothing else in the code reads `DEFAULT_RETRIES`, so it has no behavioral effect in this snapshot.
- Entry 6: what should `page_count(0, size)` return, 0 or 1? The docstring does not say. Whichever is chosen, the entry should state it.
