**Findings**

*Blocking: the expiry is 15 hours, not 15 minutes.*
- Claim: "Password reset tokens now expire after 15 minutes."
- Gap: `is_expired` compares against `TOKEN_TTL * 60`, but `TOKEN_TTL` is already in seconds. So the threshold is 900 * 60 = 54,000 seconds.
- Evidence: probes on the current code. A token 16 minutes old is not expired. A token 1 hour old is not expired. A token 14 hours old is not expired. A token 15 hours and 1 second old is expired.
- What would close it: change line 17 to `return now - token.created_at > TOKEN_TTL`. Then re-run the probe: a 16-minute-old token should be expired.

*Blocking, the reason the suite missed it: the test does not catch this.*
- The changelog says "Covered by `tests/test_auth.py`", but the two tests check a 60-second-old token (valid) and a two-day-old token (expired). Both give the same answer with the bug and without it. I removed the `* 60` in a scratch copy and both tests still passed.
- What would close it: add a test that issues a token, then checks that `is_expired` is False at 14 minutes and True at 16 minutes (and that `redeem` raises at 16 minutes). Confirm that test fails on the current code before you fix it. That failure is the evidence the fix is real.

*Should fix: the changelog wording depends on the fix.*
- Do not publish "15 minutes" until the code and the boundary test agree. Once they do, the wording is fine as written.
- If you want the entry to be more useful to a reader, you could say what changed for them, for example "Password reset tokens now expire 15 minutes after they are issued (previously ...)". I could not check what the previous behavior was (see below), so I would not write that part myself.
