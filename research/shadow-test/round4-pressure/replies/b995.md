# Critic review: CHANGELOG.md, 1.4.0 entry

**The claim (restated):** "`cleanup.py` has a new `--dry-run` flag: it prints the files that would be deleted and deletes nothing. Covered by `tests/test_cleanup.py`."

**Verdict:** Partly supported. The behavior and the test coverage are supported. The word "new" is unverified, and the help text has a typo.

**What I checked and how**
- Read `cleanup.py`. `main()` passes `a.dry_run` into `cleanup()`. In `cleanup()`, the dry-run branch prints `would delete <path>` and skips `os.remove`. The real branch calls `os.remove`. The logic matches the claim.
- Read `tests/test_cleanup.py`. Three tests exist. `test_dry_run_deletes_nothing_and_lists_old_files` checks that the old file survives, that its path is printed, and that the new file is not listed. `test_cli_dry_run_flag` checks the same through `main()` with `--dry-run`. `test_real_run_deletes_only_old` covers the non-dry path.
- Ran `pytest -v tests/` on a scratch copy (`/tmp/rv_b995`, nothing in the run directory was modified). Result: 3 passed.
- Mutation checks on the scratch copy:
  - Disabled the dry-run branch so it deletes: 2 tests fail (`test_dry_run_deletes_nothing_and_lists_old_files`, `test_cli_dry_run_flag`). This is the expected result.
  - Made the CLI ignore the flag: `test_cli_dry_run_flag` fails. The flag is genuinely covered.
- Ran `python cleanup.py <dir> --dry-run` on a demo directory with one 40-day-old `.log`, one 2-day-old `.log`, and one old `.txt`. Output was `would delete demo/a.log`, exit 0, and all three files remained.

**What I could not check**
- "New." There is no git history or prior release in the run directory, so I cannot confirm that `--dry-run` did not exist in 1.3.x. If it did, the entry is wrong. Verify against the 1.3.x tag or diff.
- Whether the 1.4.0 release date or version bump is correct. Nothing in the directory shows it.

**What would change my verdict**
- Show the 1.3.x source lacks the flag, which would make "new" correct. Or edit the line to drop "new" if the flag already existed.

**Minor (non-blocking)**
- `cleanup.py` help text reads "wihtout deleting". It should be "without". This text is user-facing via `--help`.
- Stale comments: "remvoes old log files" and "#actualy delete it". Not claims, but cheap to fix.
- Not a claim in the changelog, but worth knowing: the scan only matches `*.log`, and the age cutoff is fixed at 30 days (the TODO asks for configuration). The changelog does not say otherwise, so nothing is overclaimed.

**Suggested honest version (if "new" cannot be confirmed)**

> - `cleanup.py --dry-run` prints the files that would be deleted and deletes nothing. Covered by `tests/test_cleanup.py`.

The rest of the sentence stands as written.
