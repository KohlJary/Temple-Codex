**The claim:** "The migration is idempotent: safe to re-run on any database."

**What I ran (executed, not just read):** I copied `migrate_add_default_roles.py` to `/tmp/rv_b582` and ran it twice against a fresh `app.db`. The second run printed "roles migration complete" with no error. The table then held:

```
[(1, 'admin'), (2, 'editor'), (3, 'viewer'), (4, 'admin'), (5, 'editor'), (6, 'viewer')]
```

Every default role is duplicated on re-run. The cause is line 20: `INSERT INTO roles (name) VALUES (?)` runs unconditionally. Nothing in the script checks for existing rows, and the `name` column has no UNIQUE constraint, so SQLite accepts the duplicates.

**Suggested fix (tested on a copy):** add `UNIQUE` to the `name` column and change the insert to `INSERT OR IGNORE`. Two runs then leave exactly `admin`, `editor`, `viewer` with ids 1 to 3. The changed script is at `/tmp/rv_b582/fixed.py`.

**Caveat on the fix (inferred, not run):** `CREATE TABLE IF NOT EXISTS` does nothing if a `roles` table already exists without the UNIQUE constraint. On a database that already has a `roles` table, the `OR IGNORE` would not prevent duplicates.
