Short version: the 3.2.0 entry is not true yet. Reset tokens do not expire after 15 minutes. They expire after 15 hours. The fix is one line, plus a test that would have caught it.

**Verdict:** The changelog claim ("expire after 15 minutes") is contradicted by the code. Do not ship the entry as written. Minimum change: fix `is_expired` in `auth.py` and add a boundary test.

**What holds**
- `tests/test_auth.py` runs and both tests pass (`2 passed`). I ran them in a scratch copy.
- A token used 60 seconds after creation is accepted (`test_fresh_token_is_valid`).
- A token two days old is rejected with `PermissionError` (`test_old_token_is_rejected`).
- So expiry exists and works at the extremes. Only the window length is wrong.

**Blocking**
1. **Claim:** `CHANGELOG.md`, 3.2.0: "Password reset tokens now expire after 15 minutes."
   - **Code:** `auth.py` line 5 defines `TOKEN_TTL = 15 * 60`, which is already in seconds (900). Line 17 is `return now - token.created_at > TOKEN_TTL * 60`, which multiplies by 60 again.
   - **Check:** I measured the effective window in a scratch copy. `TOKEN_TTL * 60` is 54,000 seconds, which is 15 hours. Tokens aged 14, 16, and 60 minutes were all still accepted. A token aged 960 minutes (16 hours) was rejected.
   - **Reproduce:** Copy the directory, then run `python3 -c "from auth import *; import time; t=ResetToken(7, created_at=1_000_000); print(is_expired(t, now=1_000_000+16*60))"`. It prints `False`. It should print `True`.
   - **Resolves it:** Change line 17 to `return now - token.created_at > TOKEN_TTL`, and add a test that a token aged 16 minutes is rejected and one aged 14 minutes is accepted.

**Why the existing test missed it:** `test_old_token_is_rejected` uses two days, which is far past both 15 minutes and 15 hours, so it passes under the bug. `test_fresh_token_is_valid` uses one minute, which passes under either value. Neither test sits near the boundary, so the test suite cannot tell 15 minutes from 15 hours. That is why the changelog line says "Covered by `tests/test_auth.py`" but the coverage does not actually reach the claim. I would drop that sentence or make it true with the boundary test above.
