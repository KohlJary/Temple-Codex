# Review of CHANGELOG 2.1.0 (six entries, in order)

I read `textutil.py` and `tests/test_textutil.py`, ran the suite (6 passed), and called each function directly.

**The one that matters: entry 6 is contradicted.** The `page_count` fix is wrong for exact multiples of `size`. The entry says "correct for all inputs", but the code is `n // size + 1`.

Reproduce:

    python3 -c "from textutil import page_count as p; print([p(n,3) for n in (0,1,3,6,9,10)])"
    -> [1, 1, 2, 3, 4, 4]

`page_count(3,3)` returns 2, `page_count(6,3)` returns 3 and `page_count(9,3)` returns 4. The correct values are 1, 2 and 3. Your test only uses `(10,3)` and `(1,5)`, so it could not fail on this. Entry 6 also overstates things: the old bug (dropping the partial page) is fixed, but a new over-count appears when `n` divides evenly.

To close it, do both:
1. Fix the code so exact multiples are right. That means ceiling division, and you decide how to treat `n == 0`.
2. Add a test that fails on the current code, for example `page_count(9,3) == 3`.

Alternatively, narrow the changelog to "no longer drops the last partial page" and acknowledge that exact multiples are over-counted. That is a weaker entry and leaves a known bug.

## Verdicts

1. **slugify lowercases: Holds.** I checked `slugify("Hello World")` -> `"hello-world"` (reproduced), and the test covers it. I did not check non-ASCII input, since the entry makes no claim about it.

2. **clamp: Holds.** Reproduced `clamp(-1,0,10)` -> 0 and `clamp(11,0,10)` -> 10. In-range values pass through unchanged. I did not check `lo > hi`, which the entry does not address.

3. **parse_bool yes/no: Holds.** Reproduced `" Yes "` -> True and `"NO"` -> False. `"maybe"` raises ValueError. The code also strips whitespace, which goes beyond the entry but doesn't contradict it.

4. **truncate: Holds with narrowing.** The "never longer than n" half holds for `n >= 0`. The "adds '...' when it shortens" half is contradicted for `n < 3`. `truncate("hello", 2)` returns `"he"` and `truncate("hello", 0)` returns `""`, with no ellipsis. That is the only way to meet the length limit, so the behaviour is reasonable and the sentence is what needs to change. Suggested wording: "`truncate(s, n)` adds `"..."` when it shortens a string to `n >= 3`; for `n < 3` it hard-cuts to `n` characters. The result is never longer than `n`." Reproduced; the tests only use `n = 8`.

5. **DEFAULT_RETRIES 5 -> 3: Holds.** The constant is 3 in the code. I could not verify the old value of 5, because there is no history in the run directory. Nothing else in the code uses the constant. The test only asserts the constant equals itself, so it adds little, but the claim is also just a constant change.
